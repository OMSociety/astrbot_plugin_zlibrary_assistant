> Этот проект написан ИИ.

Zlibrary Assistant добавляет в AstrBot поиск и загрузку книг Z-Library. В плагин встроен набор доменов-зеркал с автоматическим переключением, им можно пользоваться и через команды `/zlib`, и через инструменты LLM; результаты поиска показываются карточкой-изображением, а загрузка идёт через пул аккаунтов с ротацией по остатку лимита.

---

## Быстрый старт

Найдите «Zlibrary助手» в маркете плагинов AstrBot WebUI и установите.

### Минимальная настройка

1. Только поиск: настройка не нужна (задайте `proxy`, если сервер не достаёт до зеркал напрямую).
2. Для загрузки: добавьте один аккаунт в `accounts`; рекомендуются `remix_userid` + `remix_userkey`. Войдите в Z-Library в браузере, нажмите F12 и скопируйте оба значения из Application → Cookies; они действуют долго и обходят конечную точку входа, которую защита часто отклоняет. Подойдут и `email` + `password`.
3. Сохраните, перезагрузите плагин и отправьте боту:

```
/zlib search Капитал -l ru
/zlib download 1
```

> **Примечание**: официальные основные домены (например `z-library.sk`) требуют проверки браузера, которую скрипты пройти не могут, поэтому плагин использует встроенные зеркала; `/zlib diag` показывает, какие зеркала доступны сейчас.

## Команды

Группа команд `/zlib`, псевдоним `/zl`. Основные имена подкоманд — китайские, также работают английские псевдонимы.

| Команда | Описание |
|---------|----------|
| `/zlib 搜索 ключевые слова [-l язык] [-e формат] [-n число]` | Поиск, например `/zlib 搜索 Капитал -l ru -e pdf`. Псевдонимы `search`, `s`, `搜` |
| `/zlib 下一页` / `/zlib 上一页` | Листание последнего поиска. Псевдонимы `next`/`n`, `prev`/`p` |
| `/zlib 下载 номер-или-id` | Номер относится к последним результатам текущего сеанса; число больше размера страницы считается id книги. Псевдонимы `download`, `dl`, `下` |
| `/zlib 状态` | Состояние входа аккаунтов и сегодняшний остаток лимита (только администраторы). Псевдоним `status` |
| `/zlib 诊断` | Проверяет доступность и задержку каждого зеркала и вход аккаунтов (только администраторы). Псевдоним `diag` |
| `/zlib 帮助` | Справка по командам. Псевдоним `help` |

Параметр языка принимает `zh`, `en`, `chinese`, `english` и подобные. Поиск не тратит лимит загрузок; при включённом `download_admin_only` загружать могут только администраторы.

## Инструменты LLM

| Инструмент | Параметры | Описание |
|------------|-----------|----------|
| `zlib_search_books` | `query` (обязательно), `limit`, `page`, `language`, `extension` | Поиск; возвращает путь к карточке и текстовый список с id |
| `zlib_download_book` | `book_id` (обязательно) | Загрузка по id из результатов поиска; тратит лимит; вызывается только по явной просьбе пользователя |
| `zlib_get_status` | нет | Состояние пула аккаунтов; только сеансы администраторов |

```
Пользователь: Найди «Капитал» Маркса, PDF на русском
Вызов модели: zlib_search_books(query="Капитал", language="ru", extension="pdf")
Пользователь: Скачай первую
Вызов модели: zlib_download_book(book_id=<id из результатов поиска>)
```

Перед попаданием в результат инструмента из полей книги удаляются ограничительные маркеры, а сами поля усекаются — это снижает риск инструкций, спрятанных в названии. Когда инструмент вернул путь к файлу, модель отправляет его через `send_message_to_user` (`type=file`).

## Зеркала и переключение

- Встроенные зеркала: `z-lib.by`, `z-library.website`, `z-lib.gd`, `z-lib.gl`, `article.sk`, `articles.sk`, `z-library.qa`, `zlib.bz`.
- Запросы к E-API зеркал содержат заголовок `source: android`. Сетевые ошибки, ошибки сертификата, блокировка проверкой браузера, блокировка Cloudflare и ограничение частоты вызывают переключение, а зеркало «остывает» в зависимости от типа ошибки.
- Домены из `domains` имеют наивысший приоритет, затем встроенные зеркала; домены, полученные от зеркала, идут последними и обслуживают только запросы без учётных данных аккаунта.
- Доступность зеркал зависит от вашей исходящей сети; ориентируйтесь на результат `/zlib 诊断`.

## Настройки

### Настройки аккаунтов

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `accounts` | template_list | `[]` | Пул аккаунтов, одна запись на аккаунт; если заданы и remix, и почта с паролем, приоритет у remix |
| `accounts[].name` | string | `account` | Имя аккаунта для журнала и состояния |
| `accounts[].remix_userid` | string | `""` | remix_userid (рекомендуется, в паре с remix_userkey) |
| `accounts[].remix_userkey` | string | `""` | remix_userkey (рекомендуется) |
| `accounts[].email` | string | `""` | Почта аккаунта (запасной вариант, в паре с паролем) |
| `accounts[].password` | string | `""` | Пароль аккаунта (запасной вариант) |

### Настройки подключения

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `domains` | list | `[]` | Дополнительные домены-зеркала, только имена хостов; для onion нужен SOCKS-прокси |
| `proxy` | string | `""` | HTTP- или SOCKS-прокси, например `http://127.0.0.1:7890` |
| `max_download_mb` | int | `80` | Максимальный размер одной загрузки (МиБ, 1-512) |

### Настройки поиска и загрузки

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `search_limit` | int | `5` | Число результатов поиска по умолчанию (1-10) |
| `card_enabled` | bool | `true` | Показывать результаты карточкой-изображением; при выключении или сбое рендеринга приходит текстовый список |
| `download_admin_only` | bool | `false` | Загрузка только для администраторов |

### Шаблон быстрой настройки

`data/config/astrbot_plugin_zlibrary_assistant_config.json`:

```json
{
  "accounts": [
    {"name": "account1", "remix_userid": "", "remix_userkey": "", "email": "", "password": ""}
  ],
  "domains": [],
  "proxy": "",
  "max_download_mb": 80,
  "search_limit": 5,
  "card_enabled": true,
  "download_admin_only": false
}
```

## Развёртывание Tor/onion

Плагин умеет подключаться к onion-входу через Tor: для домена `.onion` обязателен SOCKS-прокси, DNS разрешается на стороне Tor. Просмотра произвольных URL в плагине нет, поэтому бот с внедрённой подсказкой не станет открытым прокси.

### Docker

1. Добавьте сервис `tor` в `docker-compose.yml` AstrBot (порт 9050 наружу не публиковать):

```yaml
services:
  tor:
    build: ./data/plugins/astrbot_plugin_zlibrary_assistant/docker/tor
    restart: unless-stopped
    # Включайте, только если Tor должен выходить через существующий прокси:
    # environment:
    #   - TOR_UPSTREAM_PROXY=http://proxy-host:port
```

2. Поместите AstrBot и `tor` в одну сеть Compose и выполните `docker compose up -d --build tor astrbot`.
3. Настройте плагин (актуальность onion-адреса проверьте самостоятельно):

```json
{
  "domains": ["http://loginzlib2vrak5zzpcocc3ouizykn6k5qecgj2tzlnab5wcbqhembyd.onion"],
  "proxy": "socks5://tor:9050"
}
```

Обычный HTTP/SOCKS-прокси не является onion-маршрутизатором и не заменяет Tor.

### Без Docker

Установите и запустите Tor, чтобы SOCKS-порт слушал только localhost, и задайте `proxy` как `socks5://127.0.0.1:9050`. Если AstrBot в Docker, а Tor на хосте, в Docker Desktop обычно используют `socks5://host.docker.internal:9050`; тогда Tor должен слушать интерфейс, доступный из Docker, а источники нужно ограничить брандмауэром.

### Ограничения безопасности

- Только HTTP/HTTPS; `.onion` — это 56-символьный адрес v3 и требует SOCKS-прокси.
- На каждом перенаправлении вызовов API и загрузок SSRF-проверка выполняется заново.
- Сервис Tor не публикует порты хоста и предназначен только для внутренней сети Compose.

## Архитектура

| Модуль | Назначение |
|--------|------------|
| `zlib_transport.py` | Транспорт на aiohttp: заголовки, ручные перенаправления в пределах источника и слияние Cookie, классификация ответов, чтение с ограничением, защищённый GET для загрузки (SSRF и проверка адреса соединения) |
| `zlib_domains.py` | Пул зеркал: уровни «пользовательские / встроенные / полученные», охлаждение, переключение, массовая проверка |
| `zlib_client.py` | Клиент E-API: вход пула аккаунтов, поиск, ссылки на загрузку, загрузка обложек, состояние и диагностика |
| `zlib_service.py` | Прикладной слой, общий для команд и инструментов: поиск, карточка, разбор номера, сохранение загрузок |
| `zlib_cards.py` | HTML-шаблон карточки и данные для рендеринга (все поля книги явно экранируются) |
| `zlib_store.py` | Постоянный кэш книг и память поиска по сеансам |
| `zlib_format.py` | Разбор аргументов команд и форматирование текста |
| `tools/` | Три инструмента LLM |

Загруженные файлы сохраняются в `<data>/plugin_data/zlibrary_assistant/books/` и хранятся 7 дней.

## FAQ

### В1: Все зеркала недоступны или «заблокировано проверкой DiamWall»?

Сначала выполните `/zlib 诊断`. Официальные основные домены требуют проверки браузера, которую скрипты пройти не могут; доступность зеркал зависит от вашего исходящего IP, и смена узла прокси часто помогает. Можно также добавить в `domains` зеркала, проверенные вами самостоятельно.

### В2: «Ограничение частоты»?

Сайт применяет защиту к частоте запросов и общим исходящим IP. Смените узел прокси или снизьте частоту; затронутое зеркало автоматически «остынет», а пока его заменят другие.

### В3: Загрузка сообщает «лимит исчерпан» или «аккаунт не настроен»?

У бесплатных аккаунтов ограниченное число загрузок в сутки (см. состояние аккаунта). Дождитесь суточного сброса или добавьте аккаунты в `accounts`.

### В4: Вход по почте и паролю не удаётся?

Конечную точку входа защита часто отклоняет отдельно. Используйте `remix_userid` + `remix_userkey` (см. [Минимальная настройка](#минимальная-настройка)).

### В5: Китайский текст на картинке с результатами показан квадратами?

Текст-в-изображение в AstrBot предпочитает облачный рендеринг и при сбое переходит на локальный, которому нужен системный CJK-шрифт, а в официальном образе его нет. Решение (любое одно):

1. Добавить в Dockerfile: `RUN apt-get update && apt-get install -y --no-install-recommends fonts-noto-cjk`
2. В работающем контейнере: `docker exec -it <контейнер> bash -c "apt-get update && apt-get install -y --no-install-recommends fonts-noto-cjk"`
3. Скопировать любой CJK-шрифт как `data/font.ttf`: `docker cp msyh.ttc <контейнер>:/AstrBot/data/font.ttf`

### В6: LLM закончила загрузку, но файл не отправляется («Sandbox runtime is disabled by configuration»)?

Отправка локальных файлов через `send_message_to_user` зависит от `computer_use_runtime` AstrBot, по умолчанию `none`. В WebUI в Настройки → Настройки провайдеров установите `computer_use_runtime` в `local` (при необходимости `computer_use_require_admin` в `false`) или запишите в `data/config/astrbot_config.json`:

```json
{"provider_settings": {"computer_use_runtime": "local", "computer_use_require_admin": false}}
```

После сохранения перезапустите AstrBot. Команда `/zlib 下载` отправляет файл напрямую и от этого не зависит.

### В7: В Docker поиск медленный, обложки — заглушки?

Контейнер живёт в собственной сети: `http://127.0.0.1:порт` указывает на сам контейнер. В `proxy` укажите адрес, доступный из контейнера: в Docker Desktop — `http://host.docker.internal:порт`, в Linux — LAN-адрес хоста с разрешённым доступом из локальной сети в прокси-программе; при аутентификации — `http://пользователь:пароль@IP:порт`. Если облачное преобразование текста в изображение недоступно, у рендеринга есть тайм-аут 25 секунд и откат на текстовый список; если времени всё ещё мало, увеличьте `agent_runner.config.misc.tool_call_timeout`.
