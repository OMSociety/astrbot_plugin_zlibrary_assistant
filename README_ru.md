## Обзор возможностей

### Поиск книг
Просто напишите в чате, какую книгу ищете, — LLM автоматически вызовет инструмент поиска и вернёт **HTML-карточку** (обложка/название/автор/формат/размер) и текстовый список с id:

```
Пользователь: Найди «Капитал» Маркса
🤖 → zlib_search_books(query=Капитал)
    По запросу «Капитал» найдено N книг, карточка отправлена ✅
```

### Скачивание книг
Скажите — и книга скачается, файл автоматически отправится в диалог:

```
Пользователь: Скачай книгу №1
🤖 → zlib_download_book(book_id=<id из результатов поиска>)
    Скачивание завершено ✅ PDF-файл отправлен, у аккаунта осталось 9 загрузок
```

### Пул аккаунтов и контроль квот
- Настраивается несколько аккаунтов Z-Library, **у каждого аккаунта своя дневная квота скачиваний** (бесплатно — около 10 раз/день)
- При скачивании автоматически выбирается аккаунт с **наибольшим остатком на сегодня**; если всё исчерпано — отказ с подсказкой
- Поддерживаются два способа авторизации: `email+password` или `remix_userid+remix_userkey`

### HTML-карточки результатов
Результаты поиска рендерятся в единые карточки-изображения (обложка Z-Library + бейджи с метаданными); при ошибке загрузки обложки автоматически подставляется градиентная заглушка, карточка не бывает пустой.

### Классификация ошибок
Лимит IP / недействительный домен / недействительная авторизация / исчерпанная квота / сетевые сбои — всё классифицируется и переводится в дружелюбные сообщения; одиночная ошибка не ломает плагин.

## Быстрый старт

### Шаг 1: Установка

AstrBot WebUI → Маркетплейс плагинов → установить `astrbot_plugin_zlibrary_assistant` с GitHub

### Шаг 2: Минимальная настройка (чтобы заработали поиск и скачивание)

Достаточно добавить один аккаунт в `accounts` на странице настроек плагина в WebUI (рекомендуется способ remix):

1. Откройте страницу настроек плагина → в `accounts` нажмите добавление записи
2. **Рекомендуемый способ**: заполните `remix_userid` + `remix_userkey` (после входа на z-library.sk в браузере нажмите F12 → скопируйте из Cookie; действует долго и не зависит от защитного механизма эндпоинта login)
3. Либо заполните `email` + `password` (после входа remix-учётные данные получаются автоматически)
4. Если нужно несколько аккаунтов — добавьте ещё записи (пул ротируется автоматически)

После сохранения перезапустите AstrBot — можно искать и скачивать книги прямо в диалоге.

> **Примечание:** Серверам в материковом Китае нужно указать прокси в `proxy` (например, `http://127.0.0.1:7897`); зарубежным серверам можно оставить пустым. Если нужен стабильный onion-вход, см. [Развёртывание Tor/onion](#развёртывание-toronion).

### Установка зависимостей
Плагин зависит от `aiohttp` + `aiofiles` + `aiohttp-socks` + `Pillow`; AstrBot устанавливает их автоматически вместе с плагином, дополнительных действий не требуется.

## Развёртывание Tor/onion

Опционально плагин может обращаться к onion E-API Z-Library через Tor, сохраняя полную обратную совместимость с обычным доменом и HTTP-прокси. Предоставляются те же 3 LLM-инструмента:

- `zlib_search_books`: поиск книг
- `zlib_download_book`: скачивание по id из результатов поиска
- `zlib_get_status`: состояние аккаунтов и квоты

Сетевые запросы идут в Tor через SOCKS5, а DNS-разрешение `.onion` выполняется на стороне Tor. Плагин не предоставляет инструмент для произвольного просмотра URL, чтобы из-за prompt-инъекции бот не превратился в открытый прокси.

### Развёртывание в Docker

1. Установите `astrbot_plugin_zlibrary_assistant` как обычно.
2. Добавьте сервис `tor` из примера в `docker-compose.yml` AstrBot (не публикуйте порт 9050 в интернет):

```yaml
services:
  tor:
    build: ./data/plugins/astrbot_plugin_zlibrary_assistant/docker/tor
    restart: unless-stopped
    # Если Tor должен выходить в интернет через имеющийся прокси, включите по его фактическому типу:
    # environment:
    #   - TOR_UPSTREAM_PROXY=http://proxy-host:port
```

3. Убедитесь, что AstrBot и `tor` находятся в одной сети Compose, затем пересоберите и запустите:

```bash
docker compose up -d --build tor astrbot
```

4. Заполните конфигурацию плагина в AstrBot:

```json
{
  "domain": "http://loginzlib2vrak5zzpcocc3ouizykn6k5qecgj2tzlnab5wcbqhembyd.onion",
  "proxy": "socks5://tor:9050",
  "max_download_mb": 80,
  "search_limit": 5,
  "accounts": []
}
```

Обычный HTTP/SOCKS-прокси — не onion-маршрутизатор и не может заменить Tor. Плагин всегда подключается к `socks5://tor:9050`; если Tor сам нуждается в вышестоящем прокси, задайте `TOR_UPSTREAM_PROXY=http://proxy-host:port` или `TOR_UPSTREAM_PROXY=socks5://proxy-host:port` в зависимости от протокола имеющегося сервиса. Имя, адрес и порт вышестоящего сервиса заполняются по фактической конфигурации.

Настройка аккаунтов та же, что и раньше. Рекомендуется `remix_userid` + `remix_userkey`, чтобы не обращаться к эндпоинту входа слишком часто.

### Развёртывание без Docker

Установите и запустите Tor так, чтобы SOCKS-порт слушал только локальный интерфейс, затем укажите `proxy` = `socks5://127.0.0.1:9050`. Если AstrBot в Docker, а Tor на хосте, Docker Desktop обычно использует `socks5://host.docker.internal:9050`; при этом Tor должен слушать интерфейс, доступный из Docker, а источники должны быть ограничены файрволом.

### Ограничения безопасности

- Принимаются только HTTP/HTTPS; `.onion` должен быть v3-адресом длиной 56 символов.
- Запросы к `.onion` обязаны идти через SOCKS-прокси; локальное DNS-разрешение запрещено.
- Каждый переход редиректа от API заново проходит SSRF-проверку.
- По умолчанию не более 80 МиБ на один файл, чтобы аномальный ответ не исчерпал память.
- Сервис Tor не публикует порты хоста и доступен только внутри сети Compose.

### Проверка

```bash
python -m pytest -q
```

Фактическая связность также зависит от того, завершил ли Tor bootstrap, доступен ли целевой onion и действительны ли учётные данные.

## Описание параметров конфигурации

### Настройки аккаунтов

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `accounts` | template_list | `[]` | Пул аккаунтов Z-Library, один аккаунт на запись. Рекомендуется `remix_userid`+`remix_userkey` (парой) или `email`+`password` |
| `accounts[].name` | string | `account` | Пометка аккаунта (для различения в логах) |
| `accounts[].email` | string | `""` | Email аккаунта (в паре с password) |
| `accounts[].password` | string | `""` | Пароль аккаунта |
| `accounts[].remix_userid` | string | `""` | remix_userid (в паре с remix_userkey, рекомендуется) |
| `accounts[].remix_userkey` | string | `""` | remix_userkey (рекомендуется) |

### Настройки подключения

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `domain` | string | `z-library.sk` | Домен или полный базовый URL E-API Z-Library. Для обычных доменов по умолчанию используется HTTPS; можно указать и `http://...onion` |
| `proxy` | string | `""` | HTTP- или SOCKS-прокси (необязательно). Для onion-адресов обязателен Tor SOCKS, например `socks5://tor:9050` |
| `max_download_mb` | int | `80` | Максимальный размер одного скачиваемого файла (MiB, диапазон 1-512) |

### Настройки поиска

| Параметр | Тип | По умолчанию | Описание |
|--------|------|------|------|
| `search_limit` | int | `5` | Максимальное число результатов поиска по умолчанию (используется, если LLM не указал; диапазон 1-8) |

### Шаблон быстрой настройки

Заполняется в панели настроек WebUI, либо ориентируйтесь на следующую структуру (`data/config/astrbot_plugin_zlibrary_assistant_config.json`):

```json
{
  "accounts": [
    {
      "name": "account",
      "email": "",
      "password": "",
      "remix_userid": "",
      "remix_userkey": ""
    }
  ],
  "domain": "z-library.sk",
  "proxy": "",
  "max_download_mb": 80,
  "search_limit": 5
}
```

## Инструменты, вызываемые LLM

Плагин регистрирует 3 LLM-инструмента; модель сама решает, когда их вызвать, — просто сформулируйте запрос естественным языком:

```
Пользователь: Найди «Капитал» Маркса
🤖 → zlib_search_books(query=Капитал)
    По запросу «Капитал» найдено N книг, карточка отправлена ✅

Пользователь: Скачай книгу №1
🤖 → zlib_download_book(book_id=123456)
    Скачивание завершено ✅ PDF-файл отправлен, у аккаунта осталось 9 загрузок

Пользователь: Сколько книг я ещё могу скачать сегодня?
🤖 → zlib_get_status()
    Состояние пула аккаунтов Z-Library: account1 ✅ ок, сегодня скачано 1/10
```

### zlib_search_books
Поиск по библиотеке книг Z-Library по ключевым словам; возвращает карточку-изображение + текстовый список с id. Поиск **не расходует** квоту скачиваний.

| Параметр | Тип | Описание |
|------|------|------|
| `query` | string | **Обязательно**, ключевые слова (название/автор/тема, поддерживаются китайский и английский) |
| `limit` | int? | Максимум результатов (если не указано, берётся из настройки `search_limit`, максимум 8) |
| `language` | string? | Фильтр по языку, например `zh` / `en` / `fr` |
| `extension` | string? | Фильтр по формату, например `pdf` / `epub` / `mobi` |

### zlib_download_book
Скачивает книгу по id из результатов поиска и сохраняет её локально. **Вызывается только при явной просьбе пользователя скачать**; расходует дневную квоту аккаунта.

| Параметр | Тип | Описание |
|------|------|------|
| `book_id` | int | **Обязательно**, id книги (из нумерованного списка, возвращённого zlib_search_books) |

### zlib_get_status
Запрашивает состояние авторизации и остаток дневной квоты скачиваний по каждому аккаунту пула.

| Параметр | Тип | Описание |
|------|------|------|
| (без параметров) | - | - |

## Архитектура

### Клиент eapi (zlib_client.py)
Асинхронная обёртка над внутренним интерфейсом Android-клиента Z-Library (неофициальный E-API):
- На основе aiohttp, соответствует правилам разработки AstrBot (асинхронность, без requests)
- Пул аккаунтов: у каждого аккаунта своё состояние квоты; при скачивании автоматически выбирается аккаунт с наибольшим остатком
- Классификация ошибок: `rate_limited` / `auth_failed` / `quota_exhausted` / `domain_invalid` / `network_error` / `api_error`
- Кэш книг сохраняется на диск; после перезапуска AstrBot книга по-прежнему скачивается напрямую по id
- Исправление mojibake: дважды закодированный текст от Z-Library автоматически восстанавливается
- Автонормализация домена (добавляет `https://` для обычных доменов и `http://` для onion, если схема не указана; адреса с путём отклоняются); имена скачанных файлов автоматически очищаются от недопустимых в Windows символов

### Слой инструментов (tools/)
Три `FunctionTool` регистрируются через `add_llm_tools`; LLM сам распознаёт и вызывает их в диалоге:
- `search_tool.py` — поиск + рендеринг HTML-карточек (при сбое автоматический откат к простому тексту)
- `download_tool.py` — скачивание по id в `<data>/zlibrary_assistant/books/`, возвращает абсолютный путь
- `status_tool.py` — проверка состояния пула аккаунтов

### Рендеринг карточек (templates.py)
HTML-шаблоны на Jinja2 через встроенный в AstrBot преобразователь текста в изображение (`html_renderer`):
- CSS-стек шрифтов; облачный рендеринг сам подбирает китайский шрифт, локальные шрифты не нужны
- Обложки скачиваются на стороне плагина и **встраиваются как base64** (облачному рендереру не нужен доступ к внешним ссылкам Z-Library); при сбое скачивания автоматически показывается градиентная заглушка
- Названия обрезаются до двух строк, авторы сокращаются в одну строку — вёрстка длинных списков остаётся стабильной

## Часто задаваемые вопросы

### Q1: При развёртывании в Docker китайские символы на картинках с результатами поиска превращаются в квадратики/кракозябры?

**Причина**: у AstrBot «текст в изображение» два пути — облачный рендеринг (по умолчанию; шрифты в облаке, локальные не нужны) и локальный рендеринг (автоматический откат при сбое облака, рендеринг через Pillow). Локальному рендерингу нужны китайские шрифты в системе, но в официальном образе AstrBot (`python:3.12-slim`) **ни одного китайского шрифта не предустановлено**; если Pillow не находит шрифт, он использует встроенный растровый, и весь китайский превращается в квадратики.

**Решение** (любой из вариантов):
1. Добавьте строку в Dockerfile (рекомендуется; действует после пересборки образа):
   ```dockerfile
   RUN apt-get update && apt-get install -y --no-install-recommends fonts-noto-cjk
   ```
2. Установите прямо в запущенном контейнере:
   ```bash
   docker exec -it <имя_контейнера> bash -c "apt-get update && apt-get install -y --no-install-recommends fonts-noto-cjk"
   ```
3. Без установки пакетов: положите любой файл китайского шрифта (например, Microsoft YaHei `msyh.ttc`) в каталог `data/` AstrBot под именем `font.ttf`:
   ```bash
   docker cp msyh.ttc <имя_контейнера>:/AstrBot/data/font.ttf
   ```

### Q2: Пишет «Z-Library ограничивает текущий IP»?

У Z-Library жёсткий контроль частоты обращений (код ошибки `#ipd3`); общие прокси-IP (например, узлы «аэропортов») легко помечаются. Решения:
- Сменить прокси-узел (переключить узел в Clash/V2Ray)
- Либо снизить частоту запросов за короткие промежутки времени
- Плагин классифицирует эту ошибку и выдаёт дружелюбное сообщение, не падает и автоматически восстанавливается после «остывания»

### Q3: Пишет «текущий домен, возможно, недействителен»?

Домены Z-Library часто изымаются/меняются (на практике около половины привычных доменов уже не работают). Решение: замените значение `domain` в настройках плагина на текущий рабочий домен (например, `z-library.sk`, **префикс `https://` не нужен**). Работоспособность можно предварительно проверить, открыв `https://<домен>/eapi/info` (если возвращается JSON — домен действителен).

### Q4: При скачивании пишет «квота пула аккаунтов исчерпана»?

У бесплатных аккаунтов Z-Library дневной лимит скачиваний ограничен (около 10 раз/день). Решения:
- Дождаться сброса квоты на следующий день
- Добавить больше аккаунтов в настройку `accounts` (пул автоматически ротируется на аккаунт с наибольшим остатком)

### Q5: Вход постоянно выдаёт «лимит IP» (#ipd3), но сайт открывается?

**Причина**: у Z-Library отдельная защита на **эндпоинте login** (строже, чем у read-only эндпоинтов); общие IP «аэропортов» легко помечаются. Read-only интерфейсы вроде `/eapi/info` остаются доступны, но вход `email+password` отклоняется.

**Решение**: перейдите на способ **`remix_userid` + `remix_userkey`** (эндпоинт login не используется, выполняется только GET-проверка — эта защита её практически не затрагивает):
1. После того как вы хотя бы раз успешно вошли в Z-Library, получите эти два значения на странице профиля / в клиенте
2. Впишите `remix_userid` и `remix_userkey` в `accounts` настроек плагина (email/password оставьте пустыми)
3. Плагин проверит через GET `/eapi/user/profile`, и поиск/скачивание будут работать как обычно

> **Подсказка:** `remix_userkey` действует долго — настроив один раз, можно пользоваться постоянно.

### Q6: Скачивание завершилось, но файл не отправляется, ошибка "Sandbox runtime is disabled by configuration"?

**Причина**: отправка локальных файлов через `send_message_to_user` в AstrBot зависит от **локальной среды выполнения Computer Use** (`computer_use_runtime`), которая по умолчанию в AstrBot равна `none`, из-за чего локальные файлы блокируются песочницей.

**Решение** (через WebUI или файл конфигурации, на выбор):
1. **WebUI**: `Конфигурация (Config) → Настройки провайдеров → computer_use_runtime` поменять на `local` (можно также установить `computer_use_require_admin` в `false`)
2. **Файл конфигурации**: отредактируйте `data/config/astrbot_config.json` (создайте, если его нет):
   ```json
   {
     "provider_settings": {
       "computer_use_runtime": "local",
       "computer_use_require_admin": false
     }
   }
   ```
   После сохранения перезапустите AstrBot.

### Q7: Какие зависимости нужно настроить?

Плагин зависит от `aiohttp` + `aiofiles` + `aiohttp-socks` + `Pillow`; AstrBot устанавливает их автоматически вместе с плагином. Преобразование текста в изображение использует встроенные возможности AstrBot, ничего дополнительно ставить не нужно.

### Q8: При развёртывании в Docker поиск медленный / все обложки на карточках — заглушки / инструмент сообщает timeout?

**Причина**: контейнер Docker — изолированная сетевая среда; указанный в настройках `http://127.0.0.1:7897` указывает на **сам контейнер** (вашего прокси внутри нет), загрузки всех обложек падают (показываются заглушки), а облачный рендеринг из контейнера может быть недоступен, и рендеринг съедает весь таймаут инструмента (по умолчанию в AstrBot `tool_call_timeout` — 120 секунд).

**Решение**:
1. **Укажите прокси-адрес, доступный контейнеру**: формат `http://IP:порт`; если прокси требует логин и пароль — `http://логин:пароль@IP:порт` (например, `http://user:pass@IP:port`); плагин на базе aiohttp сам отправляет заголовок аутентификации `Proxy-Authorization`. В Windows/Mac Docker Desktop можно использовать `http://host.docker.internal:порт`; в Linux — LAN-IP хоста, убедившись, что в прокси включён «доступ из локальной сети»
2. Если облачный рендеринг недоступен: в плагин встроена **защита таймаутом рендеринга в 25 секунд**; при сбое рендеринга автоматически происходит откат к текстовому списку книг (инструмент целиком не падает), и если это приемлемо, ничего делать не нужно
3. Если времени всё равно не хватает: увеличьте `agent_runner.config.misc.tool_call_timeout` в настройках AstrBot (например, до `240`)
